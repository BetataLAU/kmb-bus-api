路徑參數說明

參數型別說明必填
routePath路線號碼，大小寫敏感（例：74B、1A）。Y
directionPath方向，只接受 outbound（去程）或 inbound（回程），全小寫。Y
service_typePath服務類型，常見 1（普通）或 2（特別）。Y
stop_idPath16 字元的站點 ID，大小寫敏感。Y
方向代碼的兩種寫法 「查詢網址」用 outbound / inbound； 但「回傳資料」裡的方向欄位（bound 或 dir）用的是 O / I。 兩者別搞混。

資料欄位（Data Dictionary）

回應的 JSON 結構。每個回應都有共同的 type / version / generated_timestamp / data。

共同欄位（所有回應）

欄位型別說明
typeString資料種類：Route / RouteList / Stop / StopList / RouteStop / RouteStopList / ETA / StopETA / RouteETA。
versionStringJSON 版本，例如 "1.0"。
generated_timestampString回應產生（並快取前）的時間，ISO 8601 格式（含時區）。
dataObject / Array你真正要的資料。清單類 API 為陣列，單筆類為物件。

2.1 Route / Route List

欄位型別說明例子
coString巴士公司，固定為 "KMB"（含九巴與龍運）。"KMB"
routeString路線號碼。"74B"
boundString方向：I 回程 / O 去程。"O"
service_typeString服務類型。"1"
orig_en / orig_tc / orig_scString起點（英／繁中／簡中）。"九龍灣"
dest_en / dest_tc / dest_scString目的地（英／繁中／簡中）。"大埔中心"
data_timestampString資料在來源產生時間（ISO 8601）。"2024-11-29T11:40:00+08:00"

2.2 Stop / Stop List

欄位型別說明例子
stopString站點 ID（16 字元）。"A3ADFCDF8487ADB9"
name_tc / name_en / name_scString站名（繁中／英／簡中）。"中秀茂坪"
latString緯度（WGS84 十進位度）。22.318856
longString經度（WGS84 十進位度）。114.231353
data_timestampString資料來源時間。"2024-11-29T11:40:00+08:00"

2.3 Route-Stop / Route-Stop List

欄位型別說明例子
coString巴士公司。"KMB"
routeString路線號碼。"1A"
boundString方向 I/O。"O"
service_typeString服務類型。"1"
seqNumeric站序（第幾站）。1
stopString站點 ID。"A3ADFCDF8487ADB9"
data_timestampString資料來源時間。"2024-11-29T11:40:00+08:00"

2.4 ETA / Stop ETA / Route ETA

欄位型別說明例子
coString巴士公司。"KMB"
routeString路線號碼。"40"
dirString方向：I 回程 / O 去程。"O"
service_typeNumeric服務類型。1
seqNumeric該站在此路線的站序。7
stopString站點 ID。（僅 ETA API 回應包含此欄）"A60AE774B09A5E44"
dest_tc / dest_sc / dest_enString目的地（繁中／簡中／英）。"麗港城"
eta_seqNumeric第幾班的預估（1 = 最近）。每方向最多 3 筆。1
etaString預計到站時間（ISO 8601）。可能為 null（暫無資料）。"2024-11-29T17:25:51+08:00"
rmk_tc / rmk_sc / rmk_enString備註（例如「原定班次」），可能為空字串。"原定班次"
data_timestampString資料來源時間。"2024-11-29T17:22:15+08:00"
重點 每條路線每個方向最多回傳 3 筆 ETA（eta_seq 1~3）。eta 是 null 時， 代表目前查不到該班次的預估時間（例如還沒發車），程式要能處理這種情況，不要直接當成錯誤。

狀態碼與錯誤處理

狀態碼意思回應內容
200成功正常的 JSON 資料。注意：查無資料時也是 200，但 data 為空。
422參數錯誤或缺少{ "code": 422, "message": "Invalid/Missing parameter(s)." }
或 { "code": 422, "message": "Invalid direction." }
500伺服器內部錯誤錯誤訊息（JSON）。

發生錯誤時，回應內容用 code 與 message 兩個欄位描述問題：

錯誤回應範例（422）
{
  "code": 422,
  "message": "Invalid/Missing parameter(s)."
}
查無資料範例（200，但 data 為空）
{
  "type": "Route",
  "version": "1.0",
  "generated_timestamp": "2024-11-29T15:37:44+08:00",
  "data": {}
}
實測小結
  • 方向拼錯（如 sideways）→ 422 Invalid direction.
  • 缺少參數（如少了 service_type）→ 422 Invalid/Missing parameter(s).
  • 路線不存在（如 999XYZ）→ 200，但 data 是 {}。
  • 站點不存在 → 200，但 data 是 []。
